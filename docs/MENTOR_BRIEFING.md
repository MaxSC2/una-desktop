# U.N.A. CORE — Mentor Briefing (Отчёт для ИИ-наставника)

> **Назначение:** компактный документ, который скормите мощной LLM (GPT/Claude/другая)
> для получения архитектурных советов и наставлений по проекту UNA Desktop.
> Читается за ~3 минуты. Написан как бриф для консультанта.

---

## 1. Что мы строим (философия)

**U.N.A. — не AI-модель и не приложение.** Это **программная система-компаньон**, внутри
которой AI-модели являются одним из когнитивных компонентов (примерно как «один отдел
мозга», а не весь мозг).

```
U.N.A.  (сущность, живёт вне интерфейса)
├── Perception      (голос, экран, события, система)
├── Attention       (фокус, DnD, паузы)
├── Memory          (факты/опыт/контекст/забвение) — принадлежит U.N.A., не модели
├── Identity        (характер, ценности, стиль)     — переживает смену модели
├── Emotion/State   (настроение, энергия)           — детерминированно, без LLM
├── Planning        (простые / сложные / автономные задачи)
├── Skills          (навыки, процедуры)
├── Tool System     (ПК / Web / API / файлы / код)
├── Security        (sandbox, подтверждения, приватность)
├── Resource Mgmt   (CPU / GPU / RAM / сеть / батарея / режим) — центральный орган
├── World State     (окружение)
├── Interaction     (реакции)
├── Presence        (Desktop UI / Voice / Avatar / Notifications / future)
└── Cognition       (НЕ обязана быть LLM!)
       ├── Local LLM
       ├── Cloud LLM A / B
       └── специализированные модели
```

**«Живой интерфейс» — не граница Ю.Н.А., а одно из мест её присутствия.** Аватар —
это «тело/представление» в конкретной среде, а не сама Ю.Н.А.

## 2. Текущее состояние (проверено по коду, а не по документации)

**Стек:** Electron 33 (Node 20.18) + React 19 + TS 5.9 + Vite 5 + Tailwind 3 + better-sqlite3 + nut-js.
**Целевое железо:** GTX 1650, 4 GB VRAM, 8 GB RAM, Windows. Это жёсткое ограничение.

### Что реально работает (ядро):
- Chat pipeline (stream + non-stream), единый `tool-loop`.
- 25 инструментов + реестр + MCP-fallback.
- Память: SQLite 5 уровней + FTS5 external-content + Memory Pods + граф связей + RLM (HOT/WARM/COLD) + [MEM]-токены + embeddings (Ollama + hashing-fallback).
- Identity: отдельный слой, `buildIdentityPrompt()`, переживает смену модели.
- State / Attention / Modes: детерминированные КА (без LLM).
- Resource Manager: детект gaming/compiling/meeting по процессам+окнам, TTL-кэш, VRAM-проба.
- Safety: SSRF, env-filter, protected-files, `vm`-sandbox, подтверждения.
- Фоновые движки: life-loop, background-monitor, proactive, reminders, Telegram.
- L0 Fast-path: «открой Discord» → резолвер имени → запуск БЕЗ LLM (мс).
- L1 Semantic router: embeddings → intent (fallback на regex).
- VRAM-gate: при gaming выгружает модель из Ollama (`keep_alive:0`), с проверкой `/api/ps`.
- M1–M4 уже в `git` (commit `cfb5314`); предыдущие — `1e2664a` (M2), `e2c73f1` (бриф).

## 4. Что наставник может увидеть (вопросы для совета)

1. **Архитектурный порядок «отделов мозга».** Какой минимальный устойчивый набор слоёв
   дать сейчас, чтобы не построить `CognitiveOrchestratorFactoryManagerV2`?
2. **Память как орган.** Как построить Memory Manager (значимость/уверенность/давность/
   срок актуальности + забвение) поверх SQLite + Pods + RLM + Graphiti, не дублируя их?
3. **Resource Manager как центр вычислений.** Насколько агрессивно встраивать в роутинг
   задач? Как честно решать: «быстрый маршрут / подождать ресурсы / облако»?
4. **Cognition без LLM.** Какие классы задач обязаны идти В ОБХОД LLM? Где граница
   «детерминированно + 30 строк TS» против «нужна генерация»?
5. **Presence / аватар как «тело», а не сущность.** Какой минимальный API присутствия
   заложить сейчас, чтобы позже добавить голос / мобильный / VR без переписывания ядра?
6. **Агентная система «по-настоящему».** «Отделы мозга» = разделение ответственности
   (не 20 LLM-агентов). Какие части — код, какие — сервисы/алгоритмы, какие — LLM?
7. **Что мы упускаем.** Что в текущем стеке развалится при масштабировании
   или на реальном железе (4 GB VRAM / 8 GB RAM)?

## 5. Ограничения при советах

- **Железо:** GTX 1650 4 GB VRAM, 8 GB RAM, i5, Windows. НЕЛЬЗЯ держать 2 тяжёлые модели в VRAM.
- **Личность:** UNA — женский персонаж-напарник, «не слуга и не клоун». Identity важна.
- **Приватность:** всё локально по умолчанию; облако — только по явному выбору + ключ юзера.
- **Стиль разработки:** не строить абстрактные AI-слои заранее. Любой слой обязан отвечать
  «какую конкретную проблему решает?» Если решается 30 строками TS — LLM не нужен.
- **Проверка:** после каждого изменения слоя — `npm run build` + tsc (0 ошибок), тесты.
