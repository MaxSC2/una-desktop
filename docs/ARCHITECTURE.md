## Почему Electron

**Альтернативы:** Tauri (Rust + системный webview), Python + PyQt, C# + WPF.

Электрон выбран, потому что:
1. **Кроссплатформенность** — один код на Windows/Linux/macOS.
2. **Богатая экосистема** — npm-пакеты для всего (better-sqlite3, electron-store, @xenova/transformers).
3. **Доступ к системе** — Node.js API: fs, child_process, desktopCapturer, globalShortcut, Tray.
4. **Простота разработки** — React + TypeScript + Vite = быстрая разработка.
5. **Документация** — огромное сообщество.

**Минусы Electronga:** ~100 МБ базовый размер, ~150-200 МБ RAM. Для вашего железа (8 ГБ) — приемлемо.

Если хочется лёгкости — Tauri (5 МБ базовый, ~50 МБ RAM), но потребуется Rust toolchain.

## Жизненный цикл сообщения

Когда вы пишете «удали файлы в /tmp», происходит:

1. **Рендерер** (ChatPanel) → `window.una.chat.send("удали файлы в /tmp")`
2. **Preload** транслирует в IPC: `ipcRenderer.invoke('chat:send', text)`
3. **Main process** принимает в `ipcMain.handle('chat:send', ...)`:
   - Сохраняет сообщение в **episodic memory** (SQLite)
   - Загружает контекст: последние 20 сообщений + релевантные факты (semantic memory)
   - Вызывает `chatWithTools()` — отправляет LLM
4. **LLM** (Ollama или Z.ai):
   - Получает системный промпт + контекст + инструменты
   - Возвращает: `tool_calls: [{ name: 'execute_command', args: { command: 'rm -rf /tmp/*' } }]`
5. **Safety classifier** анализирует `rm -rf /tmp/*`:
   - Паттерн `rm -rf` → уровень `dangerous`
   - Возвращает `needs_confirmation`
6. **Main process** отправляет в рендерер:
   ```json
   {
     "reply": "Требуется подтверждение...",
     "pending_confirmation": {
       "token": "exec_...",
       "action": "Выполнить: rm -rf /tmp/*",
       "risk": "dangerous",
       "details": "..."
     }
   }
   ```
7. **Рендерер** показывает ConfirmationDialog
8. Пользователь нажимает «Подтвердить» → `window.una.chat.confirm(token)`
9. **Main process** добавляет токен в `confirmedTokens` и повторяет запрос
10. LLM снова вызывает `execute_command` — теперь токен валиден, команда выполняется
11. Результат возвращается пользователю + TTS озвучивает ответ

## Идемпотентность и подтверждения

Подтверждение работает через **токены**:
- Опасная операция возвращает `token: "exec_<timestamp>_<hash>"`
- Токен сохраняется в `electron-store` (переживает перезапуск)
- При повторном запросе LLM вызывает тот же инструмент — проверяем токен
- Токены не истекают по времени, но чистятся при выходе

## Передача больших данных

- **Скриншоты**: base64 PNG ~50-200 КБ, передаётся через IPC без проблем
- **Аудио TTS**: base64 MP3 ~20-100 КБ
- **Аудио ASR**: WebM/Opus ~10-50 КБ
- **Файлы**: читаются в main process, в рендерер передаётся только текст (до 32 КБ)

## Изоляция процессов

Electron использует 2 процесса:
- **Main** (Node.js) — полный доступ к системе, fs, child_process
- **Renderer** (Chromium) — песочница, только через `window.una` (preload)

Это **безопасность**: даже если вредоносный код попадёт в рендерер (например через XSS в ответе LLM), он не сможет напрямую вызвать `fs.unlink()`. Только через наши IPC-хендлеры с проверкой.

## Работа в фоне

- `app.on('window-all-closed')` — переопределён, не выходит
- Закрытие главного окна → `mainWindow.hide()` (остаётся в памяти)
- Tray иконка всегда видна
- Overlay окно вызывается горячей клавишей
- `app.isQuitting = true` ставится только при «Выход» из tray-меню

## Lock screen — ограничения

**Windows:** обычные приложения НЕ работают на экране блокировки. Для работы нужны:
1. **Windows Service** (запуск от имени SYSTEM) — сложный путь, требует подписи
2. **Task Scheduler** с опцией «Run whether user is logged on or not»
3. **UWP приложение** с возможностью lock screen (только для store-приложений)

U.N.A. **не работает на lock screen по умолчанию**. Можно сделать сервис, который будет слушать голосовые команды через микрофон и на lock screen — это отдельный проект. Подробности в [BACKGROUND.md](BACKGROUND.md).
