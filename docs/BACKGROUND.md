# Фоновый режим и Lock Screen

## Режим работы в фоне

U.N.A. спроектирована так, чтобы **всегда быть доступной**, но не мешать.

### Tray иконка

После запуска в системном трее (рядом с часами) появляется иконка U.N.A.

**Левый клик** — показать/скрыть главное окно.

**Правый клик** — меню:
- Показать U.N.A.
- Голосовая команда (открывает overlay)
- Проверить Ollama
- Выход

### Закрытие главного окна

Когда вы нажимаете «X» в заголовке окна:
- Окно скрывается (не закрывается)
- U.N.A. остаётся в памяти
- Tray иконка активна
- Горячая клавиша работает

Полный выход — только через tray → «Выход».

### Горячая клавиша

По умолчанию: **`Ctrl+Shift+Space`**

При нажатии:
- Появляется overlay-окно (прозрачное, поверх всех окон)
- Overlay автоматически начинает слушать микрофон
- Говорите команду
- Overlay закрывается, U.N.A. обрабатывает и отвечает голосом

Изменить клавишу можно в Настройках → «Горячая клавиша».

Формат клавиш Electron:
- `CommandOrControl+Shift+Space` — Ctrl+Shift+Space (Windows/Linux) или Cmd+Shift+Space (Mac)
- `Alt+Shift+U`
- `F8`

### Запуск при старте системы

Чтобы U.N.A. запускалась автоматически:

**Windows:**
1. `Win+R` → `shell:startup`
2. Создайте ярлык на `UNA.exe` в этой папке

**Linux (systemd):**
```ini
# ~/.config/systemd/user/una.service
[Unit]
Description=U.N.A. Assistant
After=graphical.target

[Service]
ExecStart=/opt/UNA/una-assistant
Restart=on-failure

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable una.service
systemctl --user start una.service
```

**macOS:** Системные настройки → Пользователи → Объекты входа → добавьте U.N.A.

### Запуск свёрнутой

В настройках: «Запускать свёрнутой» = ON
- При запуске главное окно не показывается
- Только tray иконка
- Полезно для автозапуска

## Overlay окно

Overlay — это маленькое прозрачное окно (480×200), которое:
- Не имеет рамки
- Прозрачное (`transparent: true`)
- Поверх всех окон (`alwaysOnTop: true`)
- Не показывается в таскбаре (`skipTaskbar: true`)
- Скрывается при потере фокуса

В оверлее:
- Анимированный Orb (визуализация)
- Поле ввода команды
- Кнопка микрофона
- Текущий статус

Активируется:
- Горячей клавишей `Ctrl+Shift+Space`
- Из tray-меню → «Голосовая команда»
- Программно через `window.una.window.showOverlay()`

## Сопровождение в любых окнах

U.N.A. **может сопровождать вас** в любых открытых окнах:

### Что работает

✅ **Анализ экрана** — U.N.A. делает скриншот всего монитора через `desktopCapturer` и анализирует через VLM.
Спросите: «Что у меня открыто?» или «Помоги с этим окном».

✅ **Голосовые команды** — через overlay. Нажмите `Ctrl+Shift+Space` в любой программе, говорите.

✅ **Выполнение команд** — U.N.A. может открыть любую программу, переключить окно, выполнить shell-команду.
«Открой Chrome», «Переключись на Word», «Запусти калькулятор».

✅ **Чтение файлов** — даже если файл открыт в другой программе, U.N.A. может его прочитать.

### Что НЕ работает

❌ **Прямое управление UI других приложений** — U.N.A. не может кликнуть кнопку в чужом окне. Это ограничение безопасности ОС.

❌ **Внедрение в окна** — U.N.A. не может «встроиться» в другое приложение как плагин.

❌ **Чтение содержимого окон** — U.N.A. видит только pixels (через скриншот), не структуру данных.

### Частичное решение — автоматизация

Для автоматизации других приложений можно:
1. **AutoHotkey** (Windows) — скрипты для кликов, ввода текста
2. **xdotool** (Linux) — то же самое для X11
3. **AppleScript** (macOS) — нативная автоматизация

U.N.A. может генерировать AHK-скрипты и запускать их:
- «Напиши AHK скрипт, который открывает Chrome и переходит на google.com»
- U.N.A. создаст .ahk файл и выполнит его

Это продвинутое использование, требует установки AutoHotkey.

## Lock Screen — ограничения

### Windows

**Проблема:** На экране блокировки Windows приложения работают в режиме «Secure Desktop» — обычные процессы пользователя не запускаются.

**Что НЕ работает на lock screen:**
- Главное окно U.N.A.
- Overlay окно
- Горячая клавиша (перехватывается Winlogon)
- Tray иконка (нет explorи)

**Что МОЖЕТ работать:**

1. **Windows Service** (запуск от SYSTEM):
   - Сервис может работать на lock screen
   - Но не имеет доступа к UI (desktopCapturer, микрофон может потребовать права)
   - Сложно в разработке, требует code signing

2. **Voice activation через Cortana API:**
   - Только Windows 10+
   - Ограниченные команды
   - Не подходит для полноценного ассистента

3. **Task Scheduler с SYSTEM:**
   - Запускает процесс до входа пользователя
   - Может слушать микрофон (если права настроены)
   - Не может показывать UI на lock screen

**Реалистичное решение для lock screen:**

Сделать отдельный **Windows Service**, который:
- Запускается от SYSTEM
- Слушает ключевое слово «U.N.A.» через микрофон (Vosk, Porcupine)
- Записывает команду
- Отправляет на локальный сервер U.N.A. (через named pipe)
- Получает ответ
- Воспроизводит через динамики

Это **отдельный проект**, не входит в текущую версию. Если интересно — заведите issue, поможем.

### Linux

На Linux с X11 / Wayland:
- Экран блокировки обычно через `xscreensaver`, `i3lock`, `gnome-screensaver`
- Эти программы запускаются в отдельном X-сессии или под отдельным пользователем
- Обычные приложения пользователя НЕ видят этот экран

**Решение:**
- systemd service от root
- D-Bus активация для общения
- PulseAudio от root (сложности)

### macOS

- Lock screen более интегрирован
- Можно использовать `NSWorkspace` notifications
- Но полноценный ассистент на lock screen требует специальных entitlements

## Альтернативы для lock screen

Если вам критично нужен ассистент на lock screen:

1. **Cortana / Siri / Google Assistant** — работают на lock screen, но ограниченные
2. **Amazon Echo / Alexa** — отдельное устройство, не ПК
3. **Home Assistant** с локальным wake word (Porcupine) — может работать с ПК через MQTT

## Планы на будущее

- **Wake word** (как «Hey Siri») через Porcupine — U.N.A. будет откликаться на голос

- **Windows Service** для lock screen — отдельный компонент
- **Multi-monitor** — оверлей на конкретном мониторе
- **Voice activity detection** — автоматическая остановка записи
