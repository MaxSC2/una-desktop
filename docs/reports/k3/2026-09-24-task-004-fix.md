## Findings
1. Подтверждения из INV подтвердились на практике при написании тестов: `connectAll` с
   ответами JSON-RPC проходит handshake (`initialize` → notification → `tools/list`) полностью
   in-process; `waitForResponse`-таймауты (15/30с) в тестах не срабатывают (эхо отвечает
   микрозадачей — сьют 6 кейсов отрабатывает ~20мс вычислений).
2. Повторный `connectAll` после `disconnectAll` наполняет tools заново (новые процессы) —
   значит `initialized=false` и `tools.clear()` фактически наблюдаемы, но НЕ через публичный
   API (прямых геттеров нет; в тестах использован наблюдаемый прокси).
3. Сервер с эмитированным `exit` скипается целиком: kill не вызывается (запись заменяется
   обработчиком `mcp-adapter.ts:111-115`) — подтверждено отдельным кейсом.
4. Повторный `disconnectAll` без exit-событий вызывает `kill` повторно (попытка) и не бросает:
   идемпотентность практическая, как в INV §Q2.4.
