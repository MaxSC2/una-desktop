## Findings (зафиксированные эджи, НЕ исправлены — контракт P1-2)

### fast-path.ts
1. **Trailing-пунктуация срезается ровно один символ** (`[.!?]?`): «открой дискорд!!» → null
   (второй `!` попадает в имя приложения и ломает алиас). Одиночные `!`/`?` работают.
2. Глагол без цели («открой») → null; неизвестное приложение после всех срезов → null.
3. `runFastCommand` при throw из `dispatchTool` проглатывает исключение и возвращает
   error-текст (`result.success=false`), не пробрасывает.

### intent.ts — приоритет порядка (первый матч побеждает, факт)
4. **weather раньше greeting**: «привет, какая погода сегодня» → weather (greeting-паттерны
   ^-anchored, но weather проверяется первым и не anchored).
5. **web_search раньше file_find**: «найди файл test.txt» → web_search (`/найди/`);
   file_find достижим через «где лежит/находится», `find file`, `grep`.
6. **file_read раньше gui**: «открой файл readme» → file_read; «открой браузер» → gui.
7. **code раньше gui**: «запусти код» → code (gui-паттерны не покрывают «запусти код»).
8. `filterToolsByIntent` сохраняет порядок ВХОДНОГО массива, а не TOOL_BY_INTENT;
   неизвестные имена отфильтровываются; greeting → []; unknown → все 25 инструментов.
9. `TOOL_BY_INTENT` не экспортируется — маппинги (memory → memory_save/memory_recall/create_reminder
   и др.) проверены через поведение `filterToolsByIntent`.

### semantic-router.ts
10. Без init → `{ unknown, 0, [] }`, embed не вызывается; init при падении embed → warn,
    роутер остаётся неинициализированным (regex fallback на стороне вызывающего кода).
11. Повторный init — no-op.
12. **Порог 0.6 включителен (`>=`)**: cos ровно 0.6 → intent принят; чуть ниже → unknown.
13. При равных score побеждает intent, идущий первым в ANCHORS (stable sort).
14. `scores` (топ-3) возвращаются даже при `unknown` (confidence < порога) — но пустые при
    exception/неинициализации.
15. `SEMANTIC_CONFIDENCE_THRESHOLD = 0.6` экспортирован и проверен напрямую.
