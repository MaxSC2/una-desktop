## 2. Зафиксированные эджи (НЕ исправлены, контракт P1-2)

### 2.1. deleteGoal: subtasks-сирот НЕ остаются (расхождение с гипотезой спеки)
Спека предлагала проверить «deleteGoal оставляет subtasks-сирот если FK выключен (:memory: по умолчанию)».
**Факт первого прогона:** better-sqlite3 выставляет `PRAGMA foreign_keys = ON` по умолчанию
(в отличие от сырого SQLite), поэтому `ON DELETE CASCADE` срабатывает и сирот нет:
`getNextSubtask(goalId) → null`, `getGoalProgress(goalId).total → 0`.
Контрольный прогон с `db.pragma('foreign_keys = OFF')` подтвердил: сироты появляются только
при явном выключении FK. Тест фиксирует оба факта.

### 2.2. restoreBackupsForOperation: LIKE-wildcards в operationId
`operationId` подставляется в `LIKE '%…%'` без экранирования: `'%'` матчит ВСЕ бэкапы
(подтверждено тестом: 2 бэкапа разных операций восстановлены). `'_'` — односимвольный wildcard.

### 2.3. cleanupOldBackups: ENOENT-файл
Если .bak удалён вручную — строка всё равно удаляется из БД, счётчик растёт (тест: deleted=1).

### 2.4. formatWorkContextForPrompt: порог `lines.length > 1`
Одиночная секция из одной строки (только `workDuration > 60` или только `isLongSession`)
возвращает `''` — предупреждение о долгой сессии без других секций теряется.

### 2.5. Прочие зафиксированные факты
- `getGoalStats`: неизвестный status попадает динамическим ключом и в `total`.
- `updateSubtaskStatus` на несуществующий id — silent no-op.
- `findGitRepos` maxDepth=3: репо на глубине 4 не находится (проверка `depth > maxDepth` до проверки `.git`).
- `suggestedBreak` = `duration > 180 && duration % 60 < 5` (срабатывает только в первые 5 минут каждого часа после 3ч).
- `getRecentFiles`: строгое `mtime > now-24ч`; глубина обхода 4; стоп на 100 результатах до сортировки.
