# Prototype Scene v0.2 — композиция R1–R6

Открыть: `docs/design/prototype-scene-v0.2/index.html` (двойной клик).
Не тронуты: `src/`, `electron/`, `prototype-a1-a3/`, грамматики.
Состояния: клавиши `1` IDLE, `2` SPEAKING, `3` WORKING, текст в input,
Esc/■ — стоп. Demo-панели нет (нулевой пользовательский слой).

## Гипотеза (что проверяли)

Грамматики v0.1 работают, но сцена A1–A3 собрана как dashboard с аватаром:
ромб 54px читается как status icon, strip — как chat panel, низ перегружен,
мета-подписи объясняют систему. v0.2 меняет только композицию (R1–R6),
не грамматики: presence area 240px, conversation field без карточки,
pocket — единственная карточка, header без статуса, тихий dock.

## Проверено визуально (C1–C6, смотреть в браузере)

C1. Presence area 240px, ромб 56px внутри: сущность в пространстве, не иконка.
Слот держит будущий Rive/Live2D без переделки (размер бокса = слоту v0.1).
C2. Field без surface/border/scroll: реплики типографикой (user левее+тусклее,
Юна правее+ярче), старые уходят в глубину через opacity + mask-fade сверху.
C3. Одна карточка: только `.task` в WORKING. Больше surface-карт нет.
C4. Header: `U.N.A.` + время, без ACTIVE. Состояние — через halo/зону/строку.
C5. Иерархия: presence → utterance → field → task → dock.
C6. Вопрос ревью: место с Юной, а не dashboard. Ответ — глазами.

Регресс T1–T3/A11: CENTER→RIGHT — тот же SHIFT 500ms при неподвижном
пространстве; glow = Юна, статус = task текстом; Юна не пульсирует в такт
шагам; состояние считывается без документации.

## Что оказалось слабым (findings, не правки спеки)

W1. `presence-mark::after` рисует рамку-ромб поверх градиентного квадрата —
визуально может спорить (два ромба). Кандидат: один элемент, не два.
W2. `.field` использует `mask-image` для fade истории — старый движок
может не поддержать; fallback — просто opacity без mask (зафиксировать
в спеке при переносе).
W3. `.task` спозиционирован `absolute right 24px top 30%` — на узком экране
(<700px) налезет на presence при SHIFT right. В v0.1-Responsive pocket
становился overlay — здесь не реализовано (вне скоупа композиции).
W4. LEAN снова через `margin-left` (F1 из A1–A3 действует: семантический
LEAN, renderer-specific реализация). Не чинить здесь — чинить в renderer.
W5. Пустота вокруг presence при IDLE всё ещё требует глазной проверки:
горизонт+пол+halo могут быть недостаточны для «комнаты». Если глаз скажет
«пусто, но место» — ок; если «пустой контейнер» — композицию докручивать,
не добавляя карточки.

## Отклонения от SCENE_COMPOSITION_v0.2

D1. Voice bars сохранены (3 столбика 10px) — спека v0.2 их не отменяла,
R6 про бейдж `ЮНА` выполнен: подписи-бейджа под ромбом нет.
D2. Жизнь реплик «появилась → задержалась → поднялась → ушла» реализована
частично: появилась + задержалась + ушла в глубину (opacity), но без
поднятия (нет анимации translate вверх по истории). Полный цикл — позже.
D3. Контекстная строка `[контекст]` из схемы v0.2 не введена: R6 (правило
тишины) — элемент без функции не добавляем. Фиксирую как осознанный пропуск.
D4. STOP виден только в SPEAKING/WORKING (как в A1–A3) — в IDLE его нет,
нижняя зона не перегружена.

## Iteration 2 (2026-09-15) — conversation field + presence без бейджей

Не редизайн. Две точечные правки, без возврата chat panel / A1–A3 / статусов.

I1. CONVERSATION FIELD как постоянный слой: `.field` всегда в потоке
presence → utterance → field → spacer → dock. Пустое поле держит якорь
(`твои слова появятся здесь`) — понятно, где окажется новое сообщение.
Поле держит 3–5 последних реплик, старые уходят в глубину (opacity),
история за пределами поля не уничтожается логически (вопрос полного
доступа — следующий слой interaction design, не этот).
I2. PRESENCE AREA как область существования: бокс 240px + свободный halo,
без подписи-бейджа (убрана ещё в v0.2), без технических статусов.
Placeholder взаимозаменяем (ромб/квадрат) — сущностью его делает
пространство вокруг, а не геометрия. Слот принимает Rive/Live2D без смены
композиции.
I3. Технические статусы удалены из пользовательского слоя: в placeholder
input только `Написать Юне…`. Состояние — через поведение: IDLE центр +
дыхание; фокус input → presence `translateY(10px)` + halo ближе (LISTENING
без бейджа); SPEAKING → voice + активная реплика; WORKING → SHIFT right
+ task. Клавиши 1/2/3 — служебное управление прототипом, не интерфейс.
I4. Ритм вместо воздуха: `.place-spacer` организует пустоту между field
и dock (presence → conversation → contextual space → dock). Реплики крупнее
(15px/1.55), якорь тихий (12px). Панель не возвращена: у field нет surface,
рамки, фона, скролл-контейнера, аватаров, меток.

Проверка iteration 2 (глазами):
C1 — сущность, не icon. C2 — понятно, где живёт разговор и где появится
новое сообщение (якорь + постоянное место поля). C3 — не пусто (ритм
держат presence, utterance, field, spacer). C4 — не dashboard (одна
карточка task, только WORKING). C5 — task не ломает поле. C6 — SHIFT
одна сцена. Главный вопрос: «когда пишу Юне, очевидно ли, где появится
мой текст и где будет ответ?» История целиком — позже, не здесь.

## Iteration 3 (2026-09-15) — строгий коридор поля

Без bubbles, без chat card, без случайного размещения. 10 правил поля:
1. Фиксированный логический коридор presence→dock (`min-height: 168px`,
`justify-content: flex-end` — новая реплика всегда внизу).
2. Вертикальный поток `.field-row` с gap 8px (стабильные расстояния).
3/4. USER — левая колонка grid, YUNA — правая; стороны не меняются.
5. Gaps стабильны (один gap на поток, без исключений).
6. Старые ряды поднимаются и гаснут (is-old 0.55, is-older 0.32, cap 5).
7. Предсказуемое место: всегда последний ряд; пустое поле держит якорь.
8. Стриминг меняет существующую ячейку (`textContent` того же span).
9. Дублей нет: индикатор «Отвечаю…» живёт внутри будущей ячейки
и заменяется первым символом; `clearField` не через `innerHTML`.
10. Рамок коридора нет: ни border, ни фона, ни скролл-контейнера —
только типографика и mask-fade сверху.

Индикатор ответа: до текста — «Отвечаю…» внутри ячейки; после первого
символа исчезает (замена textContent); курсор `▌` — псевдоэлемент самой
реплики (`.field-text.field-cursor::after`); glow Юны в SPEAKING приглушён
(0.40 вместо 0.48) — текст главный, halo не конкурирует.

Проверки (глазами + руками): C2 — место разговора очевидно (якорь/поток);
C3 — коридор держит ритм даже при 2 репликах; C4 — ни одной chat card;
C5 — единственная surface — task; C6 — SHIFT не трогает поле.
Дополнительно: длинное сообщение (перенос `overflow-wrap`, коридор цел);
5+ сообщений (cap 5, старые уходят вверх); USER→YUNA→USER→YUNA (стороны
стабильны, проверить вводом 3–4 реплик подряд); стриминг без дубликатов
(один ряд на ответ, индикатор внутри).

## Validation (2026-09-15) — сверка с 10 правилами коридора

Проверено кодом и чтением (без запуска браузера claim'ом не заменяю
глазной тест, но логика сверена построчно):

1. Фиксированный коридор: `.field` имеет `min-height: 168px` +
`justify-content: flex-end` — пустое поле держит место, новая реплика
всегда внизу (последний ряд). Пустое поле показывает якорь `fieldHint`.
2. Вертикальный поток: `.field-row` в column-контейнере с `gap: 8px`.
3/4. Колонки: grid `1fr 1fr`, `.field-user → column 1 / left`,
`.field-yuna → column 2 / right`. Стороны захардкожены классом, не меняются.
5. Расстояния: один gap 8px на поток + gap 16px внутри ряда. Исключений нет.
6. Старые вверх + вторичность: `ageRows()` после каждого добавления —
последний `is-active` (opacity 1), предпоследний `is-old` (0.55),
остальные `is-older` (0.32); cap `FIELD_MAX_ROWS = 5`, старые удаляются
сверху. Mask-fade усиливает уход в глубину.
7. Предсказуемое место: всегда последний ряд; якорь `ensureLane()`
восстанавливается только когда рядов 0 (пустое поле — одна строка,
а не дубль якоря поверх реплик).
8. Стриминг меняет существующую: `addYunaStream` создаёт ряд один раз,
далее только `text.textContent = full.slice(0, i)` того же span.
9. Дублей нет: индикатор «Отвечаю…» — span внутри будущей ячейки,
первый тик заменяет его тем же `textContent` (отдельный ряд-индикатор
не создаётся); `clearField` удаляет только `.field-row`, якорь один.
Найденный и закрытый гэп: обрыв стриминга переходом состояния оставлял
`field-cursor` висеть — добавлен `finalizeStreams()` в `clearTimers()`
(курсор снимается, текст и ряд остаются, дубля нет).
10. Рамок нет: у `.field` нет border/background/скролла — только
типографика + `mask-image`. Поиск по коду: `field-line`, `msg-bubble`,
`chat-card`, `chat-bubble` — 0 совпадений; `border/background` у field —
только упоминание в README.

Иерархия: halo SPEAKING приглушён (0.40/0.12 вместо 0.48/0.14) — текст
контрастнее свечения; `.field-row.is-active` — opacity 1 против 0.55/0.32;
U.N.A. остаётся композиционным центром (presence 240px сверху, поле ниже).

Что прогнать руками (глазной тест, заменяет собой claim):
- длинное сообщение: ввод 200+ символов — `overflow-wrap: break-word`,
коридор не разъезжается, колонки стоят;
- 5+ сообщений: 6-я реплика удаляет верхний ряд, порядок не рвётся;
- USER→YUNA→USER→YUNA: 3–4 ввода подряд через input — стороны стабильны;
- стриминг без дубликатов: во время стрима один ряд с курсором внутри
реплики; Esc mid-stream — курсор снят, текст остался, дубля нет.
