## 1. Модель автономного контура

```
Kimi K3 (изолированная ветка k3/*)
  │
  ├─ анализирует репозиторий
  ├─ сам выбирает следующий шаг (внутри поставленной задачи/бэклога)
  ├─ пишет код
  ├─ запускает тесты (tsc / vitest / build / verify-manifest)
  ├─ исправляет найденное
  ├─ делает commit (монотематический, DEC-012)
  └─ пишет отчёт (контракт §5)
          ↓
   lead + совет разбирают
          ↓
   продолжаем / корректируем / merge через PR
```

Принцип: автономность **внутри зоны**, не автономность **над проектом**.
Never Ask-режим агента допустим только внутри технически изолированной зоны (§4):
документация и инструкции — это policy, а не enforcement; enforcement — git-правила
и физическое отсутствие секретов в окружении агента.

## 2. Матрица разрешений

### Разрешено (без подтверждений, внутри ветки `k3/*`)
- код репозитория (`electron/`, `src/`, `prompts/`, `scripts/`);
- тесты (`tests/`) — добавление и правка;
- research-документы и proposals (`docs/research/`, `docs/Phase2/`) — новые файлы;
- отчёты и записи (формат §5);
- коммиты в `k3/*`, push в `origin k3/*` (non-force);
- локальные проверки: `tsc`, `vitest`, `npm run build`, `verify-manifest`.

### Запрещено без отдельного разрешения lead
| Запрет | Основание |
|---|---|
| Секреты: `.env*`, SSH keys, токены, `electron-store` данные | физическая изоляция (§4), не инструкция |
| `docs/design/**` (работа дизайнера) | DEC-012: дизайн-трек — отдельные коммиты, не подхватывать |
| force-push, `reset --hard` на чужие ветки, удаление веток | необратимость; технически закрывается ruleset'ом |
| merge/PR в `main` без review lead | branch protection на `main` |
| удаление больших объёмов (каталоги, история, массовый refactor delete) | эскалация §6 |
| создание/изменение/подтверждение DEC; правка `decision-log.md`, `implementation-map.md` | DEC-010 (иерархия истины), DEC-013 (конвейер утверждений) |

### Дополнено советом (сверх исходного списка lead)
| Запрет | Почему |
|---|---|
| `electron/safety/**` (classifier, гейты, protected files) | policy-слой, DEC-002; изменение защиты самим агентом — конфликт интересов; только по задаче с отдельным DEC |
| `.github/workflows/**` (CI/release) | supply-chain: автономный агент не должен менять то, что его проверяет и что публикует релизы |
| `package.json` / `package-lock.json` (новые зависимости, bump) | новая зависимость = архитектурное решение (ср. «запрет новых подсистем до аудита») |
| Действия вне корня репозитория (системные пути, `~/.ssh`, другие проекты) | рабочая зона = репо |
| `AGENTS.md` | памятка для самих агентов; агент, правящий собственные инструкции, — анти-паттерн; правки — через proposal |

## 3. Граница DEC (ключевое правило)

K3 **не утверждает** архитектурные решения и не трактует черновики как факт.

- K3 может: исследовать, писать proposal/report, помечать `DRAFT` / `PENDING APPROVAL`,
  реализовывать **уже Accepted** DEC и утверждённые задачи.
- K3 не может: вносить записи в `decision-log.md`, менять статус DEC, опираться на
  DRAFT-DEC как на основание для кода (DEC-014…020 сейчас именно DRAFT — реализация
  M-a…M-h заблокирована до утверждения, см. `research-backlog.md`).
- Новая фундаментальная идея, найденная в работе, → файл в `docs/research/` со статусом
  PROPOSED и пункт в отчёт. Прецедент: DEC-014…020 живут черновиком в proposal и ждут lead.

## 4. Технический enforcement (policy → механизм)

Текст §2 не остановит автоматический режим сам по себе. Минимальный набор:

1. **Ветки:** `main` под branch protection (GitHub ruleset): merge только через PR,
   require review, block force-push, require status checks (существующий `ci.yml`).
   K3 работает только в `k3/<task>`.
2. **CODEOWNERS:** `docs/research/decision-log.md`, `docs/research/implementation-map.md`,
   `electron/safety/**`, `.github/workflows/**`, `AGENTS.md`, `package*.json` → owner = lead.
   Изменение этих путей в PR требует review автоматически.
3. **Секреты:** окружение K3 = клон/worktree, в котором `.env` отсутствует физически
   (реальный `.env` живёт вне рабочей зоны; в репо — только `.env.example`).
4. **Pre-merge gate:** merge в `main` только при зелёных `tsc electron 0 / tsc renderer 0 /
   vitest / build / verify-manifest` — те же счётчики, что в JOURNAL.
5. **Монотематические коммиты** (DEC-012): один коммит = одна задача; перед `git add` —
   явный `git status --short`; чужие untracked-файлы параллельных агентов не индексируются.

## 5. Контракт отчёта K3

Чтобы разбор был дешёвым, каждый автономный заход завершается отчётом
(`docs/reports/k3/YYYY-MM-DD-<task>.md` или приложением к задаче):

```
## Отчёт K3 — <дата> — <задача>
- Основание: <задача / Accepted DEC / пункт backlog>
- Ветка: k3/<task>  ·  Коммиты: <хэши, один = одна задача>
- Проверки: tsc electron <n> · tsc renderer <n> · vitest <passed>/<total> · build ✓/✗ · manifest <n>/<n>
- Отклонения от плана: <что и почему>
- Обнаружено (facts): <находки, как в JOURNAL>
- PROPOSED (PENDING APPROVAL): <идеи/DEC-драфты, НЕ решения>
- Блокеры/эскалации: <по §6>
```

---

## 6. Стоп-условия и эскалация

K3 останавливается и пишет отчёт вместо «творческого решения», если:

1. задача тянет за собой запрещённые пути (§2) — нужно разрешение lead;
2. тесты/сборка не зеленеют после 3 итераций исправлений — фиксируется состояние, стоп;
3. требования неоднозначны — `ask_clarification`-эквивалент: вопрос в отчёт, не догадка;
4. обнаружен конфликт задачи с Accepted DEC — CONFLICT-запись в отчёт;
5. объём изменения выходит за рамки поставленной задачи (scope creep) — разбить на
   отдельные задачи и эскалировать, а не расширять коммит.

## 7. DEC-021 (DRAFT) — Автономная рабочая зона K3

- **Decision:** автономный AI-кодер (K3) работает в изолированной ветке `k3/*` с полным
  циклом «анализ → код → тесты → фикс → commit → отчёт»; зона разрешений и стоп-условия —
  по §2/§6; enforcement — git-правилами и изоляцией секретов (§4); DEC-граница — по §3.
- **Date:** 2026-09-22 (DRAFT, PENDING APPROVAL).
- **Problem:** дать K3 самостоятельность без «полного root-доступа»; документированные
  запреты без технических гейтов не работают в Never Ask-режиме агента.
- **Options:** (a) полный `/auto` на всю машину; (b) только ручной режим с подтверждением
  каждого шага; (c) изолированная ветка + автоматизация внутри зоны + технические гейты.
- **Chosen:** (c).
- **Why:** (a) — необратимые риски вне зоны; (b) — теряется смысл автономки; (c) — совместимо
  с DEC-011 (GitHub как память: отчёты/коммиты сверяемы), DEC-012 (монотематические коммиты),
  DEC-013 (роли: K3 = кодер, lead утверждает).
- **Evidence:** этот документ; `.github/workflows/ci.yml`; DEC-010/011/012/013 в `decision-log.md`.
- **Affected modules:** процесс разработки; `.github/CODEOWNERS` (новый), branch rulesets,
  `docs/reports/k3/` (новый каталог).
- **Status:** Accepted (lead, 2026-09-22; внесён в `decision-log.md`).
- **Superseded by:** —.
