# U.N.A. Research Map

Структурированная карта внешних open-source проектов для U.N.A. Она заменяет использование одного
монолитного research-файла как рабочего документа.

Исходный материал сохранён отдельно: `UNA_GitHub_OpenSource_Research_v3_2026-09-12.md`.
Он остаётся журналом исследования и набором гипотез. Эта папка — навигация, решения и проверяемый
каталог. Ничто здесь само по себе не является задачей на внедрение.

## Документы

| Документ | Назначение |

| [catalog.md](catalog.md) | Полный реестр всех обнаруженных кандидатов, сгруппированных по назначению. |

## Правила чтения

- **INTEGRATE** — кандидат на небольшую, изолированную зависимость или adapter после POC.
- **ADAPT** — заимствовать интерфейс, алгоритм или отдельный модуль; не переносить приложение.
- **PATTERN** — архитектурный референс без планируемой зависимости.
- **REFERENCE** — источник идей с заметной ценой переноса.
- **AVOID NOW** — не соответствует текущему уровню зрелости, ресурсам или стеку.

`Verified` означает только, что сверены первичный репозиторий/документация на дату записи. Это не
означает, что библиотека безопасна, совместима с Electron 33 или разрешена для дистрибуции.

## Принцип отбора

Новый проект проходит через четыре вопроса:

1. Какую конкретную дыру в текущей UNA он закрывает?
2. Может ли его минимальный POC быть отключаемым и локально изолированным?
3. Не дублирует ли он уже работающий модуль?
4. Есть ли у нас тест, policy и ресурсный бюджет до включения в основной runtime?

Ответ «интересно» не является основанием добавлять зависимость.

## Текущая позиция

Сначала стабилизируется существующее ядро: tool confirmation, M6 memory manager, TypeScript и тесты.
До этого допустимы исследование, документация и независимые прототипы, но не расширение постоянного
runtime новыми агентскими фреймворками.
